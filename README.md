# 대동제·해커톤 운영 로그 정규표현식 분석

- **소속:** 전주대학교 인공지능학과
- **학번:** 202270028
- **이름:** 권상민
- **과제명:** 정규표현식 프로그램 작성 및 GitHub 업로드

## 1. 과제 소개

수업에서 제공된 대동제·해커톤 운영 로그를 읽고, 정규표현식으로 필요한 정보만 추출하는 프로그램을 만들었다. 로그에는 정상적인 정보뿐 아니라 형식이 잘못된 이메일, 자릿수가 부족한 학번, 작년 쿠폰도 함께 들어 있다. 그래서 **비슷해 보이는 문자열을 전부 가져오는 것이 아니라, 과제에서 정한 조건에 맞는 데이터만 찾는 것**을 목표로 했다.

Python의 `re` 모듈을 사용했고, 마지막에는 부스별 매출액을 숫자로 바꿔 합산했다.

## 2. 파일 구성 및 실행 방법

```text
festival_regex_submission/
├── main.py           # 정규표현식으로 데이터 추출
├── festival_log.txt  # 수업에서 제공된 로그 데이터
├── test_main.py      # 조건에 맞는지 확인하는 테스트
├── README.md         # 과제 설명
└── .gitignore
```

Python 3으로 실행할 수 있고 별도의 라이브러리 설치는 필요 없다.

```bash
python main.py
```

Windows에서 `python` 명령어가 안 되면 `py main.py`로 실행하면 된다. 다른 TXT 파일로 확인하고 싶을 때는 `python main.py 파일명.txt`를 입력하면 된다.

테스트는 다음 명령어로 실행한다.

```bash
python -m unittest -v
```

## 3. 문제별 구현 내용

### ① 이메일 주소 찾기

이메일은 `아이디@도메인` 형태인지 확인하도록 했다. 특히 `@` 뒤에 바로 점이 나오는 `hyunwoo@.ac.kr`은 정상적인 도메인이 아니므로 제외해야 한다. 참가자 명단만 검색하면 운영본부 이메일을 놓치기 때문에 **로그 전체**에서 찾도록 했다.

- 추출 결과: **5개**
- 제외한 예: `hyunwoo@.ac.kr`

### ② 휴대폰 번호 찾기

`010`으로 시작하고 중간 네 자리, 마지막 네 자리로 이루어진 번호만 찾았다. 구분자가 `-`, `.`, 공백인 경우를 모두 허용했다. 뒤에 숫자가 더 붙은 번호의 앞부분만 잘못 추출하지 않도록 앞뒤 문자도 확인했다.

- 추출 결과: **4개**
- 허용 예: `010-2345-6789`, `010.8765.4321`, `010 5544 3322`
- 제외한 예: `010-123-4567`(자릿수 부족), `063-3290-1114`(010 번호가 아님)

운영본부의 `010-9988-7766`도 조건에 맞기 때문에 결과에 포함했다.

### ③ 학번과 학과 구분하기

학번은 `202`로 시작하는 **9자리 숫자**여야 하고, `[학번 / 학과]` 형식으로 작성되어 있어야 한다. 소괄호 그룹을 이용해서 학번과 학과를 따로 가져오고 튜플로 저장했다.

여기서 중요한 부분은 `202\d{6}`이다. `202`가 세 자리이고 그 뒤의 숫자 여섯 자리를 합치면 총 아홉 자리가 된다.

```text
('202410512', '인공지능학과')
('202521088', '컴퓨터공학과')
('202230415', '전자전기공학부')
```

- 추출 결과: **3개**
- 제외한 예: `[20261122 / 데이터공학과]`(8자리), `[999900000 / 전북대학교]`(202로 시작하지 않음)

### ④ GitHub 주소와 쿠폰 찾기

GitHub는 주소에 `github.com`이 들어간다고 모두 인정하는 것이 아니라, `http://` 또는 `https://` 뒤에 `github.com/사용자/저장소` 형식이 있는지 확인했다. 따라서 `gitlab.com` 주소는 제외된다.

쿠폰은 `FEST-2026-` 뒤에 영문 대문자 또는 숫자 네 글자가 오는 형식으로 검사했다. `FEST-2025-OLD9`는 작년 쿠폰이므로 결과에 들어가지 않는다.

- GitHub 저장소: **3개**
- 2026년도 유효 쿠폰: **3개**
- 핵심 표현식: `FEST-2026-[A-Z0-9]{4}`

### ⑤ 부스별 매출 합산하기

이 부분은 금액이 여러 군데 나온다는 점을 주의했다. 예를 들어 타코야끼 부스에는 총매출 `1,350,000원`과 함께 카드 `1,100,000원`, 현금 `250,000원`이 적혀 있다. 카드와 현금 금액까지 다시 더하면 같은 매출을 중복 계산하게 된다.

그래서 **정산 구역에서 각 부스의 `매출:` 바로 뒤에 적힌 금액**만 가져왔다. 숫자 사이의 쉼표를 없앤 뒤 `int()`로 정수로 바꾸고, `sum()`으로 전체 금액을 계산했다.

| 부스 | 총매출 |
|---|---:|
| 타코야끼 푸드트럭 | 1,350,000원 |
| 불초밥 & 닭꼬치 부스 | 2,180,500원 |
| 수제 추로스 & 에이드 | 840,000원 |
| 공과대학 학생회 주점 | 1,920,000원 |
| **합계** | **6,290,500원** |

## 5. 확인하면서 알게 된 점

이번 로그를 보면 정규표현식은 단순히 문자를 찾는 것보다 **어디까지를 정상 데이터로 볼 것인지 조건을 정하는 게 중요하다**는 것을 알 수 있다. 특히 `010`이라는 글자가 있다고 해서 모두 휴대폰 번호는 아니고, 학번도 숫자가 비슷해 보여도 시작 숫자와 전체 길이를 함께 확인해야 한다.

또 이메일과 전화번호는 참가자 명단 외에도 정산 문의 부분에 있기 때문에, 처음부터 특정 구역만 검색하면 빠지는 데이터가 생긴다. 반대로 매출액은 로그 전체에서 `원`을 찾으면 쿠폰이나 카드·현금 내역까지 섞일 수 있어 정산 부분과 `매출:` 표기를 기준으로 찾았다.

형식이 잘못된 문자열도 제대로 제외되는지 확인하기 위해 `test_main.py`에 테스트를 넣었다. 실제 파일의 추출 개수와 합계까지 총 12개 테스트로 확인할 수 있다.
